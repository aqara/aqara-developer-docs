# Action

This document explains the **action blocks** in Flow.

## Overview

In Flow, **action blocks** are used to perform actions within an automation process. They represent the key nodes where operations such as device control, data processing, or other results are executed.

Action blocks typically serve as end points in an automation Flow. After a condition is met or a branch is activated, such blocks are used to trigger real operations like "turn on the light", or "modify a variable value". Each action block can support multiple inputs (allowing it to be triggered by different conditions or data sources) and multiple outputs (enabling the sequential execution of multiple actions or synchronizing results with several following blocks).

Within Flow, you can perform the following actions:
- [Device](#device): Directly send specific instructions to a single device, such as "turn on the light" or "turn off the air conditioner" for precise control.
- [Batch Execute](#batch-execute): Execute the same operation on multiple devices of the same type at once, such as one-tap turning off multiple switches, for increased efficiency.
- [Scene](#scene): Execute an existing scene to reuse its actions, without reconfiguring each device in the current flow.
- [Data Process](#data-process): Perform calculations, statistics, or string processing for use in subsequent logic.
- [Delay](#delay): Delay downstream judgement or actions for flexible process pacing.
- [Variable](#variable): Modify or toggle variable values to enable dynamic data flow.
- [Automation](#automation): Enable or disable other automations within the current automation for coordination and management.
- [Event State Hold](#event-state-hold): After an event occurs, the block sets a boolean variable to `true`, holds it for a duration, then sets it to `false`.

## Device

The device action block is used to write a custom value, a variable value, or a value from another data source to a property of a **single** specified device, or to toggle a Boolean state or run a device command with configuration parameters. Typical actions include turning a light on or off, adjusting air conditioner temperature, and toggling a switch.

### How to Use

1. Click the **+** button in the left sidebar of the canvas, and under the **Action** category, select **Device**. Choose the target device from the device list.
2. Next, you'll see a list of available blocks for that device, each representing a writable function point. Click the required block to add it to the canvas.
3. Click the block's parameter to select or input the value or state for the target device's function point.
4. After configuring the block, connect its input point to a [condition](./condition.mdx) block or [trigger](./trigger.mdx) block so that the operation will be performed when the preceding condition is satisfied.

## Batch Execute

The batch execute block writes the same value to the same function point on multiple devices of the same type, or calls a device command with the same parameters, so you can send one operation in a single step. For example, you can turn off several switches at once, or set the brightness of a group of lights to 50.

### How to Use

1. In the left sidebar of the canvas, click the **+** button, select **Batch Execute** under the **Action** category, and choose a device type from the popup list.
2. You will then see the available blocks for this type, each representing a writable function point. Click the required block to add it to the canvas.
3. Click the block's parameter to set a unified target value.

    Click the **+** button to batch-select the target devices to operate.

4. After configuring the block, connect its input point to a [condition](./condition.mdx) block or [trigger](./trigger.mdx) block so that the batch operation will be performed when the preceding condition is satisfied.

## Scene

The scene action block uses a [predefined scene](./../automation/scenes.mdx) in an automation to run the action blocks in that scene, without configuring them again in the current flow.

### How to Use

1. In the left sidebar of the canvas, click the **+** button, select **Scene** under the **Action** category to add a **Scene** action block to the canvas.
2. On the block, select the scene to reuse.
3. After configuring the block, connect its input point to a [condition](./condition.mdx) block or [trigger](./trigger.mdx) block so that the scene runs when the preceding condition is satisfied.

## Data Process

A data process block is mainly used to perform calculations, statistical aggregation, or string processing on collected data. It is a key tool for complex logic and dynamic decision-making. By flexibly processing variables, device variable, and more, you can address diverse data requirements in automation scenarios to make the flow more intelligent.

Flow supports seven common data processing methods: [Math Operation](#math-operation), [String Concatenation](#string-concatenation), [String Substring](#string-substring), [String Assignment](#string-assignment), [Case Conversion](#case-conversion), [Data Aggregation](#data-aggregation) and [Random Number](#random-number), for numeric calculations, text processing, and data statistics, respectively.

### Math Operation


A math operation block applies arithmetic, remainder, rounding, absolute value, power, square root, logarithm, exponential, min/max, bitwise or shift operations to device variable, variables or custom numbers. Reference the result in later cards or write it to a selected variable.

#### How to Use

1. In the left sidebar under **Action**, select **Data Process** and add a "Math Operation" block.

2. Click the first parameter on the block to choose a global variable, local variable, device variable, or custom value as "Number A" for the calculation.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/MathOperations-SetNumberA.png" alt="Set number A" style={{ width: '70%' }} />

3. Click the second parameter to choose the desired mathematical operator (e.g., add, substract, multiply, divide, etc.).

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/MathOperations-SetFunction.png" alt="Set function" style={{ width: '70%' }} />

4. If the operation is addition, subtraction, multiplication, division, or exponentiation, click the third parameter to set "Number B". For rounding, absolute value, or square root, this parameter is unnecessary.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/MathOperations-SetNumberB.png" alt="Set number B" style={{ width: '70%' }} />

6. Once configured, connect the block's input point to a [condition](./condition.mdx) block or [trigger](./trigger.mdx) block so the calculation runs when the preceding condition is met.

### String Concatenation

The string concatenation block converts two source values to text and concatenates them in order. You can reference the result in later blocks or write it to a selected variable or device property. Use it to combine fixed text with live data, for example joining a room name with the current temperature into one message.

#### How to Use

3. Click the second parameter to choose the second string. This can also be a variable, device variable, or custom text.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/StringConcatenation-SetStringB.png" alt="Set string B" style={{ width: '70%' }} />

4. In the final parameter, select where to output the result: a global variable, a local variable, or a device function point.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/StringConcatenation-SetOutputPath.png" alt="Set output path" style={{ width: '70%' }} />

### String Substring

The string substring block extracts text by start position and length. Positions start at 0; negative positions count from the end. If the length is longer than the remaining text, the result goes to the end of the string. If the length is 0 or negative, the result is empty. You can reference the result in later blocks or write it to a selected variable or device property.

#### How to Use

1. In the left sidebar under **Action**, select **Data Process** and add a "String Substring" block.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/StringSubstring-AddBlock.png" alt="Add a string substring block" style={{ width: '70%' }} />

2. Click the first parameter to choose a global variable, local variable, device variable, or custom text as the source string.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/StringSubstring-SetSourceString.png" alt="Set source string" style={{ width: '70%' }} />

3. Click the second parameter to set the substring rule:
    - Start position: counting starts at 0; a negative value counts from the end.
    - Length: if the length is longer than the remaining text, the result is the full remaining text; if the length is 0 or negative, the result is empty.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/StringSubstring-SetRule.png" alt="Set rule" style={{ width: '70%' }} />

4. In the final parameter, select where to output the result: a global variable, a local variable, or a device function point.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/StringSubstring-SetOutputPath.png" alt="Set output path" style={{ width: '70%' }} />

5. Once configured, connect the block's input point to a [condition](./condition.mdx) block or [trigger](./trigger.mdx) block so the substring runs when the preceding condition is met.

## Delay

The delay block inserts a specified duration of waiting within the automation Flow. By setting a delay time, you can buffer between process steps, control the pacing, or achieve timing triggers for special scenarios (e.g., delay before/after an action or judgment).

Wait for the configured duration after an upstream trigger, then continue the flow. A duration of 0 continues immediately. Use it to delay device actions or later checks.


#### How to Use

1. In the left sidebar under **Action**, select **Delay**. Click **Delay** to add the block to your canvas.
2. Click the block's parameter to set the delay duration.
3. Once configured, insert the delay block between two blocks in the process.

## Variable

Action blocks related to variables include [Set Variable](#set-variable) and [Toggle Variable](#toggle-variable). You can set a selected flow, global, or device property variable to a custom value or a source's current value, to store intermediate results or update state used by later steps.

### Set Variable

The set variable block sets a selected flow, global or device property variable to a custom value or a source's current value. Use it to store intermediate results or update state used by later steps.

#### How to Use

1. In the left sidebar under **Action**, select **Variable** and click **Set Variable** to add the block to your canvas.
2. Click the first parameter to select any global or local variable, or device variable of type string, boolean, or number.
3. Click the second parameter to set the new value.
4. Once configured, connect the block's input point to other blocks so that the variable will be modified when prior conditions are met.

### Toggle Variable

The toggle variable block reads and invert a selected boolean variable or device property: true becomes false and false becomes true. Use it to toggle an on/off state.


#### How to Use

1. In the left sidebar under **Action**, select **Variable** and click **Toggle Variable** to add the block to your canvas.
2. Click the first parameter to select a boolean variable or device variable.
3. Once configured, connect the block's input point to other blocks so that the Boolean value is toggled when conditions are met.

## Automation

Enable or disable a selected automation to control whether it responds to triggers. This card does not directly execute the target flow. Scenes cannot be enabled or disabled.

Action blocks related to process control include [Automation enable/disable · Enable](#automation-enabledisable), and [Automation enable/disable · Disable](#automation-enabledisable).

## Event State Hold

When the flow reaches this block, the block sets a selected writable boolean variable to `true` and starts the timer. If the block is triggered again before the hold duration ends, the block restarts the timer and the variable stays `true`. After the preset hold duration elapses from the last time the block was triggered, the variable is set to `false`.

#### How to Use

1. In the left sidebar under **Action**, select **Event State Hold** and add the block to the canvas.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/EventStateHold-AddABlock.png" alt="Add an event state hold block" style={{ width: '70%' }} />

2. Select the boolean variable or writable boolean device property to write to.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/EventStateHold-SelectABooleanVariable.png" alt="Select a boolean variable" style={{ width: '70%' }} />

3. Set how long the selected boolean variable stays `true`.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/EventStateHold-SetDuration.png" alt="Set the hold duration" style={{ width: '70%' }} />

4. Connect the input to a [trigger](./trigger.mdx) or [condition](./condition.mdx) block. After a trigger occurs, the target boolean variable is set to `true`.

## Loop Manage

Start or stop a selected loop trigger in this or another flow. Starting a stopped loop resets its count and waits one full interval before triggering. Starting an already running loop does not reset its count.


## Script

Run custom JavaScript. Use ctx.readVar and ctx.writeVar to read or write flow, global and device variables. Later cards can reference the latest execution result; execution exceptions report an error.


## Message Push

Send custom text or a source's current value as a text message to a DingTalk or WeCom group bot through the configured webhook. DingTalk supports a signing secret.
