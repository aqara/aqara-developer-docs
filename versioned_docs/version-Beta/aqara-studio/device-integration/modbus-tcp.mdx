# Modbus TCP

This guide explains how to connect Modbus TCP devices to Aqara Studio.

## Supported Modbus TCP Point Data Types

When integrating a Modbus TCP device with Aqara Studio, ensure that its point data types are supported by Aqara Studio, as listed below:

| Type | Range | Register Count |
|----|----|----|
| UInt16 | 0–65,535 | 1 |
| Int16 | −32,768–32,767 | 1 |
| Int32 | −2,147,483,648–2,147,483,647 | 2 |
| UInt32 | 0–4,294,967,295 | 2 |
| Float32 | IEEE 754 single precision | 2 |
| Boolean | Coil or discrete input | 1 bit |
| RegisterBit | Bits 0–15 of a single register | Within one register |
| NumericBits / EnumBits | Unsigned bit field within a single register | Within one register |
| Standard String | Holding register bytes decoded as UTF-8; currently read-only | Based on length |

## Prerequisites

Before you begin, please make sure:
- Your Modbus TCP device, Aqara Gateway, and your computer are all on the same local network.
- Your Modbus TCP device is properly configured for Modbus TCP communication. Please refer to your product manual or contact your device manufacturer for support if needed.

## Add a Modbus TCP Device

1. In the left sidebar, click to enter the **Devices** page. In the left **Protocols and Devices** panel, click the **...** button and select **Add Protocol**.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/Devices-AddProtocol.png" alt="Add Protocol" /> 

2. Select `Modbus TCP` in the popup.   
    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/Protocols-ChooseModbusTCP.png" alt="Select Modbus TCP" style={{ width: '60%' }} /> 

3. In the left **Protocols and Devices** tree, select the newly added **Modbus TCP** node, click the **Protocol Configuration** button, you can set the advanced configuration. Once the configuration is complete, click the **Close** button:   
    ![Click Protocol Configuration Button](https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/ModbusTCP-ClickProtocolConfiguration.png)

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/ModbusTCP-AdvancedConfiguration.png" alt="Advanced Configuration" style={{ width: '70%' }} />

    | Parameter             | Description |
    |-----------------------|-------------|
    | Enable/Disable Device | Note: If disabled, this device will not be available. |
    | Float Byte Order      | The byte order used for 32-bit float values. Supported orders:<ul><li>Order BADC</li><li>Order ABCD (default)</li><li>Order CDAB</li><li>Order DCBA</li></ul> |
    | Long Byte Order       | The byte order for 32-bit Int32/UInt32, which occupies two consecutive registers. Supported orders:<ul><li>Order BADC</li><li>Order ABCD (default)</li><li>Order CDAB</li><li>Order DCBA</li></ul> |

4. Click the **Add Device** button to enter the add process.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/ModbusTCP-ClickAddDevice.png" alt="Click Add Device Button" />

5. In the step 1, configure the device configuration and advanced configuration of the target Modbus TCP device. Once finished, click the **Next** button.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/ModbusTCP-AddDeviceStep1.png" alt="Add Device Step 1" />

  - Device Configuration:

    | Parameter Name | Required | Description |
    | --- | --- | --- |
    | Device Name | ✔ | The name you define for this device. |
    | Device Address | ✘ | The slave device address (unit identifier), range 0~255. |
    | IP Address | ✔ | The IP address of this device. |
    | Port | ✔ | The Modbus TCP communication port, default is 502. |
    | TCP Frame Mode | ✘ | Supported values:<ul><li>Modbus TCP</li><li>RTU Over TCP</li><li>ASCII Over TCP</li></ul> |

  - Advanced Configuration: 

    | Parameter Name | Required | Description |
    | --- | --- | --- |
    | Use Force MultIPle Coil | ✔ | Whether to use the "Force Multiple Coils" command to write multiple coils (Modbus function code 15). |
    | Use Preset MultIPle Register | ✔ | Whether to use the "Preset Multiple Registers" command to write multiple holding registers (Modbus function code 16). |
    | Float Byte Order | ✔ | The byte order used for 32-bit float values. Supported orders:<ul><li>Order BADC</li><li>Order ABCD (default)</li><li>Order CDAB</li><li>Order DCBA</li></ul> |
    | Long Byte Order | ✔ | The byte order for 32-bit Int32/UInt32, which occupies two consecutive registers. Supported orders:<ul><li>Order BADC</li><li>Order ABCD (default)</li><li>Order CDAB</li><li>Order DCBA</li></ul> |
    | Overwrite Network Configuration | ✔ | Whether to overwrite the network configuration. If not enabled, the network configuration will be used. |
    | Rx Process Mode | ✔ | Choose how received data is processed:<ul><li><strong>Byte</strong>: Byte stream mode.</li><li><strong>Packet</strong>: Packet mode.</li></ul> |

4. In the step 2, click the **Manually Add** button to start adding points.

    ![Click Manually Add Button](https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/ModbusTCP-ManuallyAdd.png)

5. In the list of function points, click the **+** button to add a new function point.

    ![Add and Configure Points](https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/ModbusTCP-AddAndConfigurePoints.png)

    After adding a point, you can configure the following parameter types for it: **Point Add**, **Type Setting**, and **Data Mapping Rules**.

    - **Point Addition**:  
        | Parameter Name      | Required | Description | Example Configuration |
        |---------------------|----------|-------------|----------------------|
        | Point Name          | ✔        | The custom name you define for this point. | - |
        | Poll Frequency   | ✘        | Controls the polling frequency of this point. Supported options: <ul><li><strong>Fast</strong>: 1 second, for high-frequency polling (suitable for key controls)</li><li><strong>Normal</strong>: 5 seconds, standard frequency</li><li><strong>Slow</strong>: 30 seconds, low frequency (for non-real-time status)</li></ul>This setting mainly takes effect when the point is read independently. If device-level polling is enabled, the actual refresh rate may follow the device polling group configuration. | Normal |
        | Data Area Type       | ✔        | Supported types:<ul><li><strong>Holding Register</strong></li><li><strong>Input Register</strong></li><li><strong>Discrete Coil</strong></li><li><strong>Discrete Input</strong></li></ul> | Holding Register |
        | Access Type         | ✘        | Supported:<ul><li>**Read Only**</li><li>**Read/Write**</li></ul> | Read/Write |
        | Address Format | ✔    | Address format type, supports:<ul><li>**Hex**: e.g., 0013</li><li>**Decimal**: e.g., 19</li><li>**Modbus**: e.g., 00001, 10001, 30001, 40001</li></ul> | Decimal |
        | Address    | ✔        | Enter the value according to the selected address format. hex example: 000A; decimal example: 10; modbus examples: 00001, 10001, 30001, 40001 | 10 |
        | Data Type           | Required for numeric points | Data type. When register type is **Holding Register** or **Input Register**, this is required. Supported:<ul><li>UInt16</li><li>Int16</li><li>UInt32</li><li>Int32</li><li>Float32</li></ul> | Int16 |
        | Unit                | Required for numeric points | Customize a suitable unit for this point. | - |
        | Bit Number          | Required for numeric points | Used to read a specified single bit from a 16-bit holding or input register. Bit numbers are zero-based and range from 0 to 15, where 0 is the least significant bit. A value of -1 indicates that this configuration is not used. | -1 |
        | Beginning Bit  | Required for numeric points | If a group of consecutive bits in a 16-bit register represents a value or state enum, fill in the start bit of this data segment. Numbered from 0, range 0-15, where 0 is the least significant bit. | 0 |
        | Number of Bits      | Required for numeric points | If a group of consecutive bits in a 16-bit register represents a value or state enum, fill in the number of consecutive bits starting from the start bit. Range: 1-16; start bit + number of bits must not exceed 16. Currently only supports extracting consecutive segments from a single 16-bit register. | 0 |
    - **Type Setting**:
        - When the register type is **Holding Register** or **Input Register**:   
            | Parameter  | Parameter Name | Required | Description | Example Configuration |
            |----------------|---------------|----------|-------------|----------------------|
            | Aqara Spec     | -             | ✔        | Associates this point with the corresponding function point in the Aqara Spec protocol for standardized control and management. | Air Conditioner/Heater Cooler/Set temperature |
            | Point Value (Number) | Min value | ✔     | The minimum value for this numeric function point. | 16 |
            |                | Max value       | ✔        | The maximum value for this numeric function point. | 30 |
            |                | Step          | ✔        | The step of the value range for this point. | 1 |
            |                | Unit          | ✔        | The unit of the value range for this point. | Celsius (℃) |
            |                | Precision     | ✔        | The precision of the value range for this point. Supported: <ul><li>Integer</li><li>1 decimal place</li><li>2 decimal places</li><li>3 decimal places</li></ul> | Integer |
        - When the register type is **Discrete Coil** or **Discrete Input**:   
            | Parameter  | Parameter Name | Required | Description | Example Configuration |
            |----------------|---------------|----------|-------------|----------------------|
            | Aqara Spec     | -             | ✔        | Associates this point with the corresponding function point in the Aqara Spec protocol for standardized control and management. | Door and Window Sensor/Contact/Contact Status |
            | Point Value (Boolean) | True text | ✔   | Display text when the boolean function point value is `true`. | Closed |
            |                | False text    | ✔        | Display text when the boolean function point value is `false`. | Open |
    - **Data Mapping Rules**: After enabled, the original physical value can be recalculated and mapped to a status. Please refer to [Numerical Mapping Functions](./../numerical-mapping-functions.mdx) for more details.
        - When the **data area type** of the point is different from the **Aqara Spec type** (for example, a numeric type needs to be mapped to a boolean type, or a boolean type needs to be mapped to a numeric type), please enable this option to achieve conversion and mapping between the physical value and the standard function point type.
        - If the **data area type** of the point and the **Aqara Spec type** are the same, you do not need to enable this option.

6. After completing the point addition, return to the **Devices** page, and you can see the newly added Modbus TCP device under the Modbus TCP node.

    Select this device, and you can see the newly added points in the **Points** list in the device details page.

    <img src="https://itad-aqara-docs-1300889962.aqara.com/dev/img/aqara-studio/en/ModbusTCP-CheckNewDeviceAndPoint.png" alt="Device Details" />
