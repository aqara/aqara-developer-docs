# Message Structure

## AuthRequest

### Description

**WebSocket authentication request**

First-message authentication flow for the Studio self-domain endpoint and LAN Studio environments; not used in production or cloud environments.

### Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `type` | string | Yes | Fixed value: [`AuthRequest`](#authrequest). |
| `version` | string | Yes | Fixed value: `v1`. |
| `msgId` | string | Yes | A non-empty identifier used by the request. It should remain unique at least among unfinished requests on the current connection. Normal responses correlate with the same msgId, while msgIds on server push messages are used only for link tracing, do not correspond to subscription request msgIds, and are not guaranteed to be globally unique.<br />Minimum length: 1. Maximum length: 64. |
| `data` | object | Yes | Business parameters. |
| `data.authType` | string | No | Authentication type. Pass `token`.<br />Fixed value: `token`. Default: `token`. |
| `data.token` | string | Yes | Use the format `Bearer <Token>`, where `<Token>` is the raw token obtained from Aqara Studio. Do not log or expose this token. |

### Example

**bearerToken**

```json
{
  "type": "AuthRequest",
  "version": "v1",
  "msgId": "10001",
  "data": {
    "authType": "token",
    "token": "<accessToken>",
    "clientId": "<clientId>"
  }
}
```

## UnsubscribeAllRequest

### Description

**Unsubscribe from all or selected devices request**

Clears subscriptions for all or selected device data and also clears Trait subscriptions for the current session.
It does not clear standalone event subscriptions or precise object-event subscriptions, and it does not disable the default DEVICE_ADDED and DEVICE_REMOVED events received on authenticated connections.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |

Normal responses correlate with the same msgId, while msgIds on server push messages are used only for link tracing, do not correspond to subscription request msgIds, and are not guaranteed to be globally unique.<br />Minimum length: 1. After subscribing to all traits of a specified device through SubscribeAllRequest or subscribing to a specified Trait of a specified device through SubscribeTraitValueRequest, when the value of the target Trait changes, Aqara Studio will push this message to you. For information on Aqara's existing Traits and their data types, see [Aqara Data Model Tags](https://docs.aqara.com/docs/aqara-developer/aqara-data-model-specification/aqara-data-model-tags/).

All business notifications now carry studioId/eventId pair; ordinary historical messages allow omission for compatibility with legacy producers. ## AlarmEvent

### Description

**Raw Alarm Push**

Delivered only to sessions that explicitly subscribe to `ALARM`. `SubscribeAllRequest` and object event subscriptions do not enable this implicitly. Alarms are independent of App notification-bar pushes. Delivery is not limited to `OFF_NORMAL`; consume the `sourceState` actually published by the alarm source. Only real-time pushes are supported, and historical alarms are not redelivered. Re-subscribe after disconnection. `msgId` is for tracing only and is not a globally unique event ID.

WebSocket and HTTP shared raw alarm-push payload. WebSocket explicitly subscribes to `ALARM` to receive, and HTTP enables alarms according to configuration; does not use the app notification payload.

All business notifications now carry studioId/eventId pair; ordinary historical messages allow omission for compatibility with legacy producers. Ordinary request/response messages do not reference this structure. Execution results and the four new scene object events have additional identity constraints.

## SubscribeObjectEventRequest

### Description

**Subscribe to space, device-space relationship, and automation object events**

Incrementally adds object-event subscriptions for the current WebSocket session; duplicate subscriptions are idempotent.

When `objectIds` is omitted, null, or an empty array, subscribe to all currently accessible objects under the specified `eventTypes`; when non-empty, subscribe only to the specified objects.

## ObjectEvent

### Description

**Object event push**

Device add/remove events are pushed by default; changes to spaces, automations, standalone scenes, and space relationships are delivered according to precise object subscriptions. Current 19 object event types are provided with examples.

DEVICE_ADDED and DEVICE_REMOVED are pushed by default after an authenticated connection is established.

DEVICE_SPACE_UPDATED, the three SPACE_* changes, the four AUTOMATION_* changes, the four SCENE_* changes, and AUTOMATION_EXECUTION_RESULT and SCENE_EXECUTION_RESULT are delivered only to SubscribeObjectEventRequest sessions that match the eventType, objectId, and current permissions.

DEVICE_ENDPOINT_* and DEVICE_TRAIT_PARAMETER_UPDATE continue to follow the existing device-data subscriptions.

Independent scenes are managed through `/scenes`, and change notifications use four `SCENE_*` event families, still using `AUTOMATION_*` for automation. Trustworthiness is determined by the server. No separate event is provided for count changes. Creating or deleting an automation sends only the corresponding lifecycle snapshot and does not additionally send a space-relationship event. For an existing object, `AUTOMATION_SPACE_UPDATED` is sent only when its space relationship changes. If both the content and the relationship change at the same time, both types of events may be received.

Independent scenes use `SCENE_ADDED/REMOVED/UPDATED/SPACE_UPDATED`, no longer sending `AUTOMATION_*`; the `sceneId` still uses the `auto_` prefix. Old automation manual entries still belong to automation. Scene definition comparison excludes space, and space and definition changes in the same batch generate two different `eventId` notifications.

The `manualTriggers` field in an automation snapshot contains `triggerNodeId` and `triggerName`. Adding, deleting, or renaming a manual trigger entry returns the full list through `AUTOMATION_UPDATED`. Replace the cache with the full list, and clear previous entries when the array is empty. No additional event subscription type is required.

msgId is used only for trace correlation. New business notifications are idempotent by `studioId` + `eventId`; old object changes without a common identity are idempotently handled based on object state, and should not be deduplicated solely by `objectId`, `eventType`, or `time`.


The new `AUTOMATION_EXECUTION_RESULT` and `SCENE_EXECUTION_RESULT` events notify per effective action record, for automations and scenes respectively. They are not completion events for an entire execution. Both Studio and Gateway are covered. A native optimization is notified once per native call. An unconfirmed result is unknown and is not expanded into per-device successes.

The two new events and the four independent scene changes must carry the common-layer `studioId` and `eventId`. The same notification identity is kept across channels and HTTP retries. The action results can be trimmed according to the receiver's permissions. They are idempotent by `studioId` + `eventId`. `executionId` only correlates an execution and is explicitly `null` when unavailable. A new subscription may receive records that the shared queue has not yet delivered. Historical replay is not provided.

All business notifications now carry studioId/eventId pair; ordinary historical messages allow omission for compatibility with legacy producers. Ordinary request/response messages do not reference this structure. Execution results and the four new scene object events have additional identity constraints.

## UnsubscribeObjectEventRequest

### Description

**Unsubscribe from space, device-space relationship, and automation object events**

Removes specified object rules or clears specified event types for the current WebSocket session.

When `objectIds` is non-empty, only the specified objects are removed; when omitted, null, or an empty array, all object rules for the corresponding `eventTypes` are cleared.
All-object subscriptions do not support excluding selected objects. To switch from all objects to specified objects, first clear the event type and then send a new specified-object subscription.

### Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `type` | string | Yes | Fixed value: [`UnsubscribeObjectEventRequest`](#unsubscribeobjecteventrequest). |
| `version` | string | Yes | Fixed value: `v1`. |
| `msgId` | string | Yes | A non-empty identifier used by the request. It should remain unique at least among unfinished requests on the current connection. Normal responses correlate with the same msgId, while msgIds on server push messages are used only for link tracing, do not correspond to subscription request msgIds, and are not guaranteed to be globally unique.<br />Minimum length: 1. Maximum length: 64. |
| `data` | array&lt;object&gt; | Yes | Must contain 1 to 100 unsubscribe items; an empty array is a parameter error and does not mean unsubscribing from all event types.<br />When objectIds is omitted, null, or an empty array, all object rules under the corresponding eventTypes for the current session are removed; when non-empty, only the specified objects are removed.<br />Minimum items: 1. Maximum items: 100. |
| `data[].eventTypes` | array&lt;string&gt; | Yes | Minimum items: 1. Items must be unique. <div><span>Allowed item values</span><ul className="enum-list"><li><code>DEVICE_SPACE_UPDATED</code>: The device's space changed.</li><li><code>SPACE_ADDED</code>: Space added.</li><li><code>SPACE_REMOVED</code>: Space removed.</li><li><code>SPACE_UPDATED</code>: Space updated.</li><li><code>AUTOMATION_ADDED</code>: Automation added.</li><li><code>AUTOMATION_REMOVED</code>: Automation removed.</li><li><code>AUTOMATION_UPDATED</code>: Automation updated.</li><li><code>AUTOMATION_SPACE_UPDATED</code>: The automation's space changed.</li><li><code>AUTOMATION_EXECUTION_RESULT</code>: Automation execution result.</li><li><code>SCENE_EXECUTION_RESULT</code>: Scene execution result.</li><li><code>SCENE_ADDED</code>: Scene added.</li><li><code>SCENE_REMOVED</code>: Scene removed.</li><li><code>SCENE_UPDATED</code>: Scene updated.</li><li><code>SCENE_SPACE_UPDATED</code>: The scene's space changed.</li></ul></div> |
| `data[].objectIds` | array&lt;string&gt; or null | No | List of object IDs. Fill in device, space, automation, or scene IDs according to the event types.<br />When subscribing, omitted, null, or empty objectIds means all objects within the current permission scope; when non-empty, only the specified objects are matched.<br />When unsubscribing, omitted, null, or empty objectIds means clearing all rules for the corresponding eventTypes; when non-empty, only the specified objects are removed.<br />Within the same WebSocket session, at most 1000 distinct objectIds may be cumulatively subscribed under each eventType.<br />When objectIds is non-empty, the eventTypes in the same item must belong to the same public ID family (device, space, automation/scene); SPACE_ADDED, AUTOMATION_ADDED, and SCENE_ADDED support only the all-objects semantic.<br />Maximum items: 1000. Items must be unique. Minimum item length: 1. |

## CommandReport

### Description

**Gateway command execution result**

Sent with v1 device-level or full-device subscriptions, preserving the original gateway result without indicating that the device physical action has been completed.

All business notifications now carry studioId/eventId pair; ordinary historical messages allow omission for compatibility with legacy producers. Ordinary request/response messages do not reference this structure. Execution results and the four new scene object events have additional identity constraints.

### Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `type` | string | Yes | Fixed value: [`CommandReport`](#commandreport). |
| `version` | string | Yes | Fixed value: `v1`. |
| `msgId` | string | Yes | A non-empty identifier used by the request. It should remain unique at least among unfinished requests on the current connection. Normal responses correlate with the same msgId, while msgIds on server push messages are used only for link tracing, do not correspond to subscription request msgIds, and are not guaranteed to be globally unique.<br />Minimum length: 1. Maximum length: 64. |
| `data` | object | Yes | Push payload data. |
| `data.deviceId` | string | Yes | Minimum length: 1. |
| `data.sequence` | integer | Yes | Minimum: `1`. |
| `data.timestamp` | integer | Yes | Studio recorded time<br />Minimum: `0`. |
| `data.did` | string | Yes | Minimum length: 1. |
| `data.reportTime` | integer or null | Yes | Gateway original report time |
| `data.source` | string or null | Yes | — |
| `data.data` | object | Yes | Additional properties are allowed. |
| `data.content` | object | Yes | Additional properties are allowed. |
| `eventId` | string | No | An opaque string for this logical notification. It must contain at least one non-whitespace character. Store and compare it as-is without relying on its format. It remains unchanged across channels and HTTP retries. Consecutive notifications with the same content use different values.<br />Minimum length: 1. Pattern: `\S`. |
| `studioId` | string | No | The official Studio identity that publishes the notification. It must contain at least one non-whitespace character. It is not a gateway identity or an authentication credential.<br />Minimum length: 1. Pattern: `\S`. |
| `code` | integer (int32) | Yes | Processing result code. 0 indicates success, and any non-zero value indicates failure. |
| `message` | string or null | Yes | Processing result message. |

`eventId` and `studioId` must appear together.
